## 一、三十秒看懂

**把手上所有复习资料丢进去，然后你就能问它、查它、让它出题考你——每个答案都告诉你出自哪份资料的第几页。**

## 二、它是给谁用的

### 用户画像

**正在备考的人**：期末考试、考研、考证（法考 / CPA / 教资 / 考公）。

他们的共同点：
- 资料多——教材 + 老师讲义 + 往年真题 + 论文，动辄十几个 PDF、几千页
- 时间少——离考试就剩几周
- **必须找到原文依据**——记错一个概念，考试就丢分

### 他们今天的四个困境

1. **找一个知识点，靠翻。** 在几十个 PDF 里搜关键词，搜出来还要判断这是哪一版、属于哪一章，翻完半小时过去了。
2. **通用 AI 不敢信。** 它不知道你老师讲过什么，会非常自信地编出教材上没有的结论。你要的是"依据"，不是"听起来对"。
3. **想自测，没题。** 真题做完了，想再练只能自己找题、自己对答案，效率极低。
4. **考前想快速过一遍，只能自己划重点。** 一章几十页，整理成要点就要一整个晚上。

### 用了之后

| 以前 | 现在 |
|---|---|
| 翻 12 个 PDF 找一个概念 | 一句话问，几秒拿到答案，附带出处 |
| 复制一段话去搜，反复换关键词试 | 直接丢半句话进去，跳到原文那一段 |
| 拿通用 AI 的答案去猜真假 | 每条结论点开就是原文那一页，高亮 |
| 自己找题、自己对答案 | 圈一章，自动出题并判分，指出你漏掉的原文 |
| 花一晚上把一章整理成要点 | 一键压成一页，考前十分钟过一遍 |

## 三、用户能做什么

### 1. 建一个资料库

按科目或考试建库，比如「操作系统期末」「考研数学」「法考-民法」。

- 每个库独立存放自己的资料与索引
- 库与库之间互不干扰，问「操作系统」不会串到「考研数学」

### 2. 上传资料

支持 PDF、Word、Markdown，也可以直接粘贴网页链接。

- 上传后自动解析：识别章节标题、剔除页眉页脚、**表格整块保留**
- 显示解析进度；若某份文件解析失败，会明确告诉你原因
- **上传后可以"预览分片结果"**——你能亲眼看到系统把你的文档切成了哪些块，切得不合理可以换一种策略重新切

> 这个预览功能是给用户看的，不是给工程师看的。切得不好，你自己就能发现。

### 3. 问 —— 对话问答（核心）

像聊天一样提问，答案基于你的资料生成。

**你会看到：**
- 答案逐字流式出现，不用干等
- 每句结论后面有小角标 `1` `2`
- 答案下方列出「答案依据」，每条包含：文件名、章节、页码、原文片段
- 点任意一条，直接跳到 PDF 对应页并高亮那句话

**关键特性：资料里没有的，它会说"没找到"。** 不会编。这是它和通用聊天机器人最大的差别。

### 4. 查 —— 原文定位

不想问问题，只想找那句话。

- 输入关键词、一个术语、甚至半句记不完整的话
- 直接返回最匹配的原文段落列表，按相关度排序
- 点开即定位

比在 PDF 里 Ctrl+F 强的地方在于：**它认语义**。你记得的是"那个说切换开销很大的地方"，不是"上下文切换"这四个字，它也能找到。

### 5. 练 —— 自动出题

选定范围（比如"第 3 章"或"这份讲义"），自动生成练习题。

**你会看到：**
- 选择题、简答题，全部基于你资料里的原文
- 你答完后，它对照原文判分
- 答错的题会指出：**你漏了原文里的哪一句**，并给出那一段

这是把"资料库"变成"私人助教"的那一步。

### 6. 理 —— 章节要点

把一章内容压缩成一页要点，按原文章节结构组织。

- 适合考前快速过一遍
- 每条要点都能点回原文，不是凭空总结

## 四、三步上手

1. **建库**：点「新建资料库」，起个名字，比如「操作系统期末」
2. **丢资料**：把教材、讲义、真题 PDF 拖进去，等解析完成
3. **开始问**：在对话框敲下第一个问题

就这三步。没有注册、没有配置、没有 API Key——**打开网址就能用**。

## 六、它做不到什么（诚实边界）

写清楚做不到什么，比吹能做到什么更让人信。

| 做不到 | 说明 |
|---|---|
| 不回答资料以外的内容 | 它只认你上传的东西。资料里没有就会说"没找到依据"，不会用模型自己的知识补答案 |
| 不支持扫描件、照片 | 纯图片的 PDF 解析不出来。请上传文字版 PDF |
| 复杂公式与图表可能识别不准 | 数学公式、流程图这类内容的解析质量有限 |
| 不是通用聊天机器人 | 它不会陪你闲聊，也不会写作文。它只干"围绕你的资料"这一件事 |
| 免费版每日提问有上限 | 每人每天 50 次——API 费用是我自己掏的，请手下留情 |

## 七、常见问题

**Q：我的资料会被别人看到吗？**
A：不会。每个资料库只对创建它的浏览器可见。

**Q：为什么它给出的答案是"教材里的话"而不是"通俗解释"？**
A：因为它的任务是帮你**找到依据**，而不是替教材重新讲一遍。原文怎么写的，它就怎么给你，这样考试时你写的是原话。

**Q：同一个问题，为什么有时答案分段和上次不一样？**
A：流式生成的措辞会有细微差别，但**依据的原文段落是稳定的**——这也正是为什么每条答案都要标出处。

**Q：分片预览是干嘛的？我看不懂。**
A：它显示的是你的文档被切成了哪些片段——系统就是靠这些片段去检索的。如果你发现某个关键段落被切断了，可以换一种切分方式重来。

**Q：能不能加扫描版教材？**
A：暂时不行，需要先做 OCR，不在当前范围内。

## 八、附录：为什么它的答案可信（技术藏在这里）

用户看到的只是"答案 + 出处"，但要让这件事成立，背后每一步都不能少。这是把技术要求翻译成用户价值：

| 技术上的做法 | 用户实际感受到的好处 |
|---|---|
| **结构化分片**（按章节标题、表格整块切） | 问某章内容时答案不会缺半句；问表格里的数据不会答错行。若按固定字数硬切，"老师在第 4 章补充过"这类句子会被切散，永远搜不到 |
| **父子分块**（小块检索、大块返回） | 检索时命中精准，回答时上下文完整，不会断章取义 |
| **混合检索**（语义向量 + 关键词） | 口语化提问（"进程线程啥区别"）能命中专业术语；学科代号、编号也能精确匹配 |
| **Rerank 重排** | 3412 页资料里，真正相关的那几段被排到最前面，而不是"看起来像"的那几段 |
| **拒答阈值** | 资料里没有就明确说没有，不编造 |
| **引用溯源** | 每个角标都能跳到 PDF 对应页并高亮那句话 |
| **全栈 + Docker 部署** | 同学打开一个网址就能用，不用装任何东西 |

> 这些技术不是"为了用而用"。**少任何一环，用户都会直接感受到"它开始不靠谱了"。**

## 九、为什么它值得放进简历

因为它是一个**有人会真的用**的东西，而不是一个技术演示。

- 目标用户明确：备考的人，第一版直接找同学试用
- 价值可验证：能说出"帮同学省了多少翻资料的时间"
- 技术有深度：分片与检索策略的优化有实测数据支撑（消融实验表）
- 完整度高：从产品定义到线上部署，整条链路都跑通了
