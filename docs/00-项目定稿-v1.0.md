## 1. 项目定义

| 项 | 内容 |
|---|---|
| 项目名 | **问书**（英文代号 DocMind） |
| 仓库名 | `wenshu`（GitHub，公开仓库） |
| 一句话 | 把备考资料变成能问、能查、能出题的私人助教，每个答案都标明出自哪份资料的第几页。 |
| 目标用户 | 正在备考的人（期末 / 考研 / 考证）。第一版直接找同班同学试用 |
| 核心价值 | **让用户敢信答案**——有出处、能跳原文、没有依据时明确拒答 |
| 技术主张 | 知识库答不准，绝大多数时候不是模型不行，而是分片和检索没做好。 |
| 展示受众 | 面试官、GitHub 访客、同学 |

### 演示语料（必须具体，不留空泛）

| 用途 | 语料 | 为什么选它 |
|---|---|---|
| 主语料 | 一门真实课程的复习资料包：教材 PDF + 老师讲义 + 往年真题 | 这就是目标用户的真实资料形态；教材结构规整，能体现结构感知分片的价值，也方便直接找同学试用 |
| 压力语料 | 一份表格极密集的 PDF（如统计年鉴、财经类教材章节） | 验证「表格整块保留」——表格一旦被切开，数据类问题必然答错 |
| 边界演示 | 一份扫描版 PDF | 主动演示"解析失败并明确告知原因"，比藏着不测更可信 |
| 明确不支持 | 扫描件 / 纯图片 PDF | OCR 不在范围内，README 中明确写出边界 |

## 2. 范围冻结

### 必做（Must）

**面向用户的（先做，这是产品存在的理由）**

1. 文档上传与解析（PDF / Markdown / Word / 网页链接）
2. **对话问答**：流式回答 + 引用角标 + 点角标跳转原文并高亮
3. **原文定位**：纯检索模式，丢半句话直接定位到原文段落
4. **自动出题**：圈定范围生成练习题，答完对照原文判分并指出漏掉的句子

**支撑上述能力的（后做，用户看不见但决定成败）**

5. 4 种分片策略可切换，且支持**分片结果实时预览**
6. 父子分块 + 元数据落库（文件 / 章节路径 / 页码 / 块序号）
7. 双路召回（向量 + 全文）+ RRF 融合 + Rerank 重排
8. 检索调试台（可视化召回与打分全过程）
9. 评测面板 + 消融实验表
10. Docker Compose 部署 + GitHub Actions CI/CD
11. **匿名访客与库口令共享**：无注册体系下的身份与隔离（visitor_id + kb_visitor 绑定表），口令支持跨设备访问与同学共用（v1.2）

### 可选（Should，时间富余再做）

- 章节要点一键压缩
- 语义分块（成本较高，先作为对比项）
- 上下文增强分块（LLM 生成块前缀）
- 查询改写 / 多查询
- 多知识库切换

### 明确不做（Won't）

| 不做 | 原因 |
|---|---|
| 用户注册与账号体系 | 吃掉一周工作量且破坏"打开即用"体验；以匿名访客 + 库口令替代（见 §5 / §7，v1.2）。不做密码、找回、个人资料 |
| 后台管理与权限体系 | 同上 |
| 移动端适配与小程序 | 演示场景是桌面端 |
| 在线协同编辑 | 与核心能力无关 |
| 模型训练与微调 | 本机无独显，且偏离「检索做准」的主线 |
| 扫描件 OCR | 解析质量不可控，明确写入边界 |

## 3. 前端页面（冻结，共 4 个）

| 路由 | 页面 | 内容 |
|---|---|---|
| `/` | 知识库列表 | 新建知识库、卡片列表、文档数统计 |
| `/kb/:id` | 文档管理 | 上传、解析进度、**分片预览**（切换策略实时看切分结果） |
| `/chat/:kbId` | 对话 | SSE 流式回答、引用角标、点击弹出原文片段 |
| `/debug/:kbId` | 调试与评测 | Tab1 检索调试台；Tab2 评测面板与消融表 |

**分片预览**与**检索调试台**是两个必须做扎实的页面，它们承担"让评委看懂你在做什么"的任务。

## 5. 数据模型（DDL 冻结）

```sql
CREATE EXTENSION IF NOT EXISTS vector;

CREATE TABLE knowledge_base (
  id              BIGSERIAL PRIMARY KEY,
  name            VARCHAR(64)  NOT NULL,
  description     VARCHAR(255),
  chunk_strategy  VARCHAR(32)  NOT NULL DEFAULT 'STRUCTURE_AWARE',
  embed_model     VARCHAR(64)  NOT NULL DEFAULT 'bge-small-zh-v1.5',
  embed_dim       INT          NOT NULL DEFAULT 512,
  share_code      VARCHAR(6)   NOT NULL UNIQUE,         -- 库口令（v1.2）：大写字母+数字，剔除 0O1I
  created_by      VARCHAR(64)  NOT NULL,                -- 创建者 visitor_id（v1.3，重置口令权限判定）
  created_at      TIMESTAMPTZ  NOT NULL DEFAULT now()
);

-- v1.2 新增：库与访客（浏览器）的绑定关系，创建者与输口令加入者都在此表
CREATE TABLE kb_visitor (
  kb_id       BIGINT       NOT NULL REFERENCES knowledge_base(id) ON DELETE CASCADE,
  visitor_id  VARCHAR(64)  NOT NULL,
  created_at  TIMESTAMPTZ  NOT NULL DEFAULT now(),
  PRIMARY KEY (kb_id, visitor_id)
);

CREATE TABLE document (
  id          BIGSERIAL PRIMARY KEY,
  kb_id       BIGINT       NOT NULL REFERENCES knowledge_base(id) ON DELETE CASCADE,
  file_name   VARCHAR(255) NOT NULL,
  file_type   VARCHAR(16)  NOT NULL,
  size_bytes  BIGINT       NOT NULL,
  page_count  INT,
  token_count INT,
  status      VARCHAR(16)  NOT NULL DEFAULT 'PENDING',  -- PENDING/PARSING/INDEXING/READY/FAILED
  error_msg   TEXT,
  created_at  TIMESTAMPTZ  NOT NULL DEFAULT now()
);
CREATE INDEX idx_document_kb ON document(kb_id, created_at DESC);

CREATE TABLE chunk (
  id           BIGSERIAL PRIMARY KEY,
  document_id  BIGINT       NOT NULL REFERENCES document(id) ON DELETE CASCADE,
  parent_id    BIGINT       REFERENCES chunk(id) ON DELETE CASCADE,
  strategy     VARCHAR(32)  NOT NULL DEFAULT 'STRUCTURE_AWARE',  -- 分块策略标记（v1.5，消融实验用）
  content      TEXT         NOT NULL,
  token_count  INT          NOT NULL,
  section_path VARCHAR(512),
  page_no      INT,
  chunk_index  INT          NOT NULL,
  embedding    vector(512),
  content_tsv  tsvector,
  created_at   TIMESTAMPTZ  NOT NULL DEFAULT now()
);
CREATE INDEX idx_chunk_doc    ON chunk(document_id, chunk_index);
CREATE INDEX idx_chunk_parent ON chunk(parent_id);
CREATE INDEX idx_chunk_tsv    ON chunk USING GIN(content_tsv);

CREATE TABLE query_log (
  id            BIGSERIAL PRIMARY KEY,
  kb_id         BIGINT      NOT NULL,
  visitor_id    VARCHAR(64) NOT NULL,
  question      TEXT        NOT NULL,
  retrieved     JSONB,      -- [{chunkId, vectorScore, ftsScore, rrfScore, rerankScore}]
  chosen_ids    BIGINT[],
  answer        TEXT,
  latency_ms    INT,
  prompt_tokens INT,
  completion_tokens INT,
  created_at    TIMESTAMPTZ NOT NULL DEFAULT now()
);
CREATE INDEX idx_query_log_kb ON query_log(kb_id, created_at DESC);

CREATE TABLE eval_question (
  id             BIGSERIAL PRIMARY KEY,
  kb_id          BIGINT      NOT NULL,
  question       TEXT        NOT NULL,
  type           VARCHAR(16) NOT NULL,   -- FACT / MULTI_HOP / TABLE / NO_ANSWER
  gold_chunk_ids BIGINT[],
  gold_answer    TEXT        NOT NULL
);

CREATE TABLE eval_run (
  id                  BIGSERIAL PRIMARY KEY,
  kb_id               BIGINT      NOT NULL,
  config              JSONB       NOT NULL,  -- 本次启用了哪些策略
  hit_rate_at5        NUMERIC(5,4),
  mrr                 NUMERIC(5,4),
  citation_accuracy   NUMERIC(5,4),
  faithfulness        NUMERIC(5,4),
  detail              JSONB,
  created_at          TIMESTAMPTZ NOT NULL DEFAULT now()
);
```

### 索引策略说明

- **不预先建 HNSW 向量索引**。块数在 5 万以内时，顺序扫描比 HNSW 更快且不占内存；超过后再建：
  `CREATE INDEX idx_chunk_vec ON chunk USING hnsw (embedding vector_cosine_ops) WITH (m=16, ef_construction=64);`
  这一点写进 README，是很实在的工程判断。
- 中文全文检索需自带分词：用 jieba 分词后在应用层生成 `content_tsv` 写入，避免依赖 zhparser 扩展。
- **库口令明文存储的取舍**：共享面板需随时向创建者重新展示，哈希后无法再显示；防爆破靠验证接口按 IP 限流（10 次/小时）。此方案是"可用性隔离"而非认证安全，边界在 README 中如实声明。

## 6. 参数冻结表

| 参数 | 冻结值 | 说明 |
|---|---|---|
| 子块大小 | 320 token | 中文约 200~260 字 |

| 父块大小 | 1024 token | 返回给模型的单元 |
| 向量维度 | 512 | bge-small-zh-v1.5 |
| 相似度度量 | 余弦 | |
| 向量召回 topK | 50 | |
| 关键词召回 topK | 50 | |
| RRF 常数 k | 60 | 经验值 |
| 融合后候选上限 | 30 | 去重后 |
| Rerank 保留 | 8 | |
| 最终上下文 | 4 个父块，≤ 3000 token | |

## 7. API 契约（冻结，10 个）

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/api/kb` | 创建知识库 |
| GET | `/api/kb` | 知识库列表 |
| POST | `/api/kb/{id}/documents` | 上传文档，返回 `documentId`，异步解析 |
| GET | `/api/documents/{id}/status` | 解析进度（status + 进度百分比 + 错误信息） |
| POST | `/api/kb/{id}/chunks/preview` | **分片预览**：传 strategy 与文件，不入库，直接返回切分结果 |
| POST | `/api/chat` | 提问，SSE 流式返回：`token` / `citation` / `done` 三类事件 |
| GET | `/api/debug/{queryId}` | **检索调试**：返回 retrieved 全量打分、chosen_ids、耗时拆解 |
| POST | `/api/eval/run` | 跑评测集；`GET /api/eval/report/{runId}` 取报告 |
| POST | `/api/kb/{id}/locate` | **查模式**：丢半句话/关键词定位原文段落，不进 LLM（v1.7） |
| POST/GET/DELETE | `/api/kb/{id}/eval/questions` | 评测题录入/列表/删除（D17 标注工具）+ `GET /eval/stats` 进度统计（v1.8） |
| POST | `/api/kb/join` | **输口令绑定资料库**（body: code；头带 X-Visitor-Id；成功返回 kbId+name；404 口令不存在；429 限流）（v1.2） |
| POST | `/api/kb/{id}/code/reset` | 重置口令（仅创建者可调），旧口令即刻作废（v1.2） |
| GET | `/api/kb/{id}/documents` | 资料库下的文档列表（含状态/进度/错误信息）（v1.4，资料管理页需要） |
| POST | `/api/kb/{id}/debug-query` | **调试台**：只跑检索链不进 LLM，返回漏斗/四列得分/耗时，结果落 query_log（v1.6） |
| GET | `/api/kb/{id}/debug/recent` | 最近查询列表（调试台首页，v1.6） |

> **请求头约定（v1.2）**：所有业务请求携带 `X-Visitor-Id`——前端首次访问生成 UUID 存 localStorage，axios 拦截器统一附加。知识库列表/详情一律按 `kb_visitor` 关联过滤；跨库访问 document/chunk 前先校验绑定关系，防越权。

### SSE 事件约定

```
event: token      data: {"text":"..."}
event: citation   data: {"chunkId":123,"file":"xx.pdf","page":12,"section":"3.2"}
event: done       data: {"latencyMs":1840,"promptTokens":2100}
```

## 8. 评测方案（冻结）

- **规模**：50 条人工标注问题
- **题型分布**：事实型 25 / 多跳 10 / 表格型 8 / 无答案 7
- **指标口径**：
  - `HitRate@5` = 标准 chunk（或其后代块）出现在前 5 的比例
  - `MRR` = 标准 chunk 排名的倒数均值
  - `引用准确率` = 回答中引用条目里，真正支撑该句结论的比例（人工抽检 30 条）
  - `忠实度` = 回答内容全部有原文依据的比例（LLM 作裁判 + 人工抽检 20 条）
- **消融实验 7 个配置**（逐行只加一个变量）：
  1. 固定 512 分块 + 纯向量
  2. 递归分隔符 + 纯向量
  3. 结构感知分块 + 纯向量
  4. + 父子分块
  5. + 双路召回 + RRF
  6. + Rerank
  7. + 上下文增强分块

## 9. 里程碑与验收标准

### M1（第 1 周）主链路跑通
**验收条件（可演示）**：上传一门课的教材与讲义 → 问"进程和线程的区别" → 得到带页码引用的回答，点角标能跳到 PDF 对应页并高亮。
包含：项目骨架、PG+pgvector 初始化、PDF/Markdown 解析、固定长度分块、纯向量召回、SSE 问答、引用跳转、资料管理页、对话页。

### M2（第 2 周）检索做准 + 原文定位
**验收条件（可演示）**：同一问题在「固定长度」与「结构感知 + 父子 + Rerank」两套配置下，调试台能并排展示召回差异；表格类问题能命中整张表格而非碎片；「查」模式丢半句记不全的话能定位到原文。
包含：结构感知分块、父子分块、元数据落库、中文全文索引、双路召回 + RRF、Rerank、分片预览、检索调试台、原文定位模式。

### M3（第 3 周）出题自测 + 评测上线
**验收条件（可演示）**：圈定"第 3 章"生成 5 道题，答完能判分并指出漏掉的原文句子；公网可访问；评测面板一键跑出 7 行消融表；README 含架构图、消融表、演示链接。
包含：出题与判分、50 条评测集、指标计算、评测面板、服务器部署、限流、README、技术博客。

## 10. 技术选型冻结（含不选理由，面试会问）

| 选型 | 选择 | 为什么不选替代方案 |
|---|---|---|
| 向量库 | PostgreSQL + pgvector | 省一个组件，向量与业务数据同库同事务；20 万块以内性能足够。不选 Chroma（偏 demo，生产特性弱，还要多一个容器），不选 Milvus（本量级属于杀鸡用牛刀，且 2C4G 吃不下） |
| 应用框架 | Spring Boot 3.x | 目标岗位匹配 |
| RAG 框架 | **不使用** LangChain / LlamaIndex | 其默认分片不贴合中文与文档结构，封装过深难自定义；**自研分片器与检索链本身就是本项目的技术产出** |
| 生成模型 | DeepSeek API | 中文效果好、价格低、可直连 |
| 向量与重排 | bge-small-zh + bge-reranker，ONNX 跑 CPU | 本机无独显；本地推理省钱，且"能不用 GPU 跑起来"是加分项 |
| 前端 | Vue 3 + Vite + TS + Element Plus | 上手快，后台类页面生态好 |
| 部署 | Docker Compose + Actions + GHCR | 详见 02 号文档 |

## 11. 风险与应对

| 风险 | 影响 | 应对 |
|---|---|---|
| 中文全文检索分词效果差 | 关键词召回失效 | 用 jieba 在应用层生成 tsvector；若仍不理想，降级为「向量召回 + 关键短语 LIKE 匹配」 |
| Rerank 在 2C4G 上延迟过高 | 首字延迟变差 | 限制候选数至 30；仍慢则降级为纯 RRF，并在文档中记录性能对比数据 |
| PDF 解析质量差 | 分片污染 | 明确只支持文本型 PDF；解析后用规则剔除页眉页脚、目录页 |
| 表格被切开 | 表格类问题答错 | 结构感知分块中表格整块保留并加标记，评测集中专门设 8 道表格型题验证 |
| 服务器成本 | 演示站下线 | 本地 docker compose 可完整运行，部署只是加分项；先保证本地可跑通 |
| 时间不足 | 无法完成 | Must 优先级最高；Should 项可整体砍掉，不影响项目完整性 |
| 公开站被刷 | API 额度损失 | 按 IP 限流 50 次/日 + max_tokens 上限 + 单文档大小限制 |
